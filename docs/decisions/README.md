# TAP Client Hub Decisions

Use one dated Markdown record per material decision. Do not silently resolve a conflict between production behavior, code, schema, product guidance, or a contract.

Each decision record must include:

- Context and evidence.
- Options considered.
- Decision and approval status.
- Rationale and consequences for implementation, operations, security, migration, and maintenance.
- Follow-up owner and revisit trigger.

Use `Proposed`, `Approved`, and `Superseded` as statuses.
